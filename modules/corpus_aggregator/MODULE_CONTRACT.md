# RB-CORPUS-AGGREGATOR Module Contract

Module ID: RB-CORPUS-AGGREGATOR  
Module Name: Corpus Aggregator  
Version: 0.1.0  
Execution Stage: 400  
Authority: MCR 2026-08-19-CA  

## Mission

Aggregate validated per-document `.corpus.json` artifacts produced by RB-PROVENANCE into one deterministic `kb.corpus.json` knowledge artifact for downstream use by Digit.

## Input Boundary

The module accepts only files ending in:

`*.corpus.json`

The following are explicitly excluded from input discovery:

- `kb.corpus.json`
- `kb.corpus.json.tmp`
- `.rag.json`
- `.chunks.json`
- Markdown source documents
- policy index records
- Chainlog records

Source corpus artifacts are read-only evidence.

## Controlled Identity

The controlled identity key is:

`(root_document_id, revision_id)`

A root document with `revision_id=NONE` is distinct from every revision belonging to that root.

An exact duplicate exists when the following all match:

- Root Document ID
- Revision ID
- Canonical SHA-256

A conflict exists when Root Document ID and Revision ID match but Canonical SHA-256 differs.

Conflicts fail closed.

## Output

Primary artifact:

`kb.corpus.json`

Temporary replacement artifact:

`kb.corpus.json.tmp`

The final implementation will:

1. Build aggregate content deterministically.
2. Compare generated bytes against an existing `kb.corpus.json`.
3. Skip the write when byte-identical.
4. Write changed output to the temporary artifact.
5. Flush and close the temporary artifact.
6. Replace the target atomically.
7. Never modify individual source `.corpus.json` artifacts.

## Ordering

Aggregate serialization will use deterministic ordering by:

1. Root Document ID
2. Revision ID
3. Chunk identity

Filename order and filesystem enumeration order are not authoritative.

## Authority Boundary

RB-CORPUS-AGGREGATOR does not establish controlled-document authority.

Authority must already have been established upstream by RB-PROVENANCE.

The aggregate is derived knowledge, not a new authority source.

## Failure Behavior

The module will fail closed for:

- malformed corpus input;
- missing required authority metadata;
- conflicting controlled identity;
- malformed chunk records;
- deterministic serialization failure;
- aggregate write failure;
- atomic replacement failure.

Exact duplicates are skipped and logged.

## Qualification Baseline

Version 0.1.0 establishes 12 qualification tests, including mandatory negative validation for conflicting controlled identity.

Aggregate serialization remains disabled in the initial skeleton revision.
